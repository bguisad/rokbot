多端原生客户端。 Self-hosted Bot Host.
Native clients everywhere.

把 Agent 服务端（Host）和共享 Linux 执行桌面（box）用 Docker 部署在你自己的服务器上。自选 OpenAI 或 Anthropic 兼容模型，对话、文件与 API Key 全部留在本地，桌面、手机与网页端只连你自己的 Host。 Run the agent server (Host) and shared Linux desktop container (box) in Docker on your own machine. Bring your own OpenAI- or Anthropic-compatible models, keep conversations, files and API keys local, and connect macOS, Windows, iOS, Android and web clients only to your Host.

核心功能Core features

保留完整的 Agent 工具与多端体验，把模型接口、数据存储、网络接入和客户端更新全部收归你自己的服务器。 Keep the full agent workflow and multi-device experience while bringing model endpoints, data storage, networking, and client updates under your own server.

共享云电脑与实时接管Shared Bot computer & live takeover
Host 自带一台所有 Bot 共用的 Linux 桌面执行容器（box），内置浏览器、终端与独立工作区卷；也可替换为远程 Linux 执行节点。客户端可随时打开实时 VNC 画面，用键鼠或触摸直接接管；Bot 也能经由客户端主动连接操作你的 Mac（命令与图形界面）或 Windows（本机命令），电脑无需开放端口。 The Host ships with a single Linux desktop execution container (box) shared by all Bots, with browser, terminal and dedicated home/workspace volumes — or swap in a remote Linux node. Open live VNC in any client to take over with mouse, keyboard or touch. Bots can also work on your Mac (shell + GUI) or Windows PC (local shell) over an outbound client connection with no open ports.
多端接力与通知Continuity across devices & notifications
对话和配置保存在 Host 上，所有客户端连接同一台 Host：电脑上布置的任务，在手机或浏览器里接着看和回复。会话按最后消息排序分组（待处理、未读、已读，Android 另有进行中）。通知支持 iOS（APNs / Bark）、Android（直连、ntfy、UnifiedPush、FCM、Webhook）及网页浏览器通知，可选每条回复或仅任务完成提醒。 Conversations and settings live on the Host so you can start on desktop and follow up on mobile or web. Chats group into Needs attention, Unread and Read (plus In progress on Android). Notifications work via APNs/Bark on iOS, persistent connection or ntfy/UnifiedPush/FCM/Webhook on Android, and browser alerts on web — on every reply or task completion only.
自选模型与备用链Bring your own models & fallbacks
兼容 OpenAI Chat Completions、OpenAI Responses 与 Anthropic Messages 三种格式。默认路由与单个 Bot 路由可分别指定模型、思考强度和最多 8 个备用模型：仅在主模型尚未输出内容且遇到 402/408/429/5xx 或网络错误时切换，避免重复输出与重复执行工具。亦可选配 JEV 智能路由（默认关闭）。 Connect OpenAI Chat Completions, OpenAI Responses, or Anthropic Messages endpoints. Set default and per-Bot routes with reasoning effort and up to 8 fallbacks. Fallback switches only on 402, 408, 429, 5xx or network errors before output starts — never mid-stream — preventing duplicate output or tool calls. Optional JEV routing is off by default.
图片与视频生成Image & video generation 需服务商 KeyRequires provider key
在管理页「图片与视频」接入 OpenAI 兼容图片/视频接口、WaveSpeed 或自定义 HTTP JSON 接口。图片生成、视频生成、视频理解与视频审核可分别指定默认模型，生成结果直接作为附件返回对话。需要自行配置对应服务商的 API Key。 Connect OpenAI-compatible image/video APIs, WaveSpeed, or custom HTTP JSON endpoints from the admin console. Configure separate default models for image generation, video generation, video understanding and video review, with outputs returned directly as chat attachments. Requires your own provider API keys.
语音对话Voice 实时通话为实验功能Real-time calls experimental
语音识别支持 Fish Audio 或 OpenAI 兼容转写服务，Mac 也可使用本地模型。语音通话复用当前 Bot 的模型、上下文和工具，由你配置的识别与合成服务驱动。实时通话目前为实验功能。 Speech recognition supports Fish Audio or OpenAI-compatible transcription services, plus local models on Mac. Voice calls use the active Bot’s model, context and tools with your configured STT and TTS services. Real-time voice calls are currently experimental.
定时任务Scheduled tasks
Host 内置本地 cron 计时器，按计划自动触发 Bot 的例行巡检或汇总任务，不依赖外部调度服务。同一任务同时只运行一次，错过的触发时间点会合并成一次补跑。 A built-in local cron scheduler inside the Host triggers Bot routines with no external scheduler required. Each routine runs at most once concurrently, and missed windows merge into a single catch-up run.
Webhook
在管理页为指定 Bot 创建外部触发入口，配置任务模板、事件类型过滤与每分钟调用上限。请求使用 HMAC-SHA256 签名校验（±5 分钟时间窗），地址与密钥仅在创建时展示一次并支持重置，每次触发留存运行记录。 Create per-Bot HTTP triggers with task templates, event-type filters and per-minute rate limits. Requests are verified with HMAC-SHA256 signatures over a ±5-minute window; URLs and secrets are shown once at creation (and can be reset), with every delivery logged.
自动审查与审批卡片Auto-review & approval cards
Bot 执行 Shell 命令、MCP 调用、电脑操作、写入定时任务或启动子 Agent 等风险操作前，由你配置的模型按规则评估，并支持自定义允许与拦截规则。被拦截的操作以原生审批卡片呈现，默认 30 分钟过期（可通过 ROKBOT_AUTO_REVIEW_APPROVAL_TTL_MS 调整），在客户端设置中开启。 Before risky actions — shell commands, MCP calls, computer use, scheduled-task writes, or sub-agent launches — your configured model checks them against built-in and custom allow/block rules. Blocked actions appear as native approval cards (30-minute default expiry via ROKBOT_AUTO_REVIEW_APPROVAL_TTL_MS). Enabled in client settings.
用量统计Usage statistics
按模型记录输入、输出、缓存读写与推理 Token。管理页「概览」和客户端设置内均提供今日（按小时）、近 7 天和近 30 天（按天）用量图表、模型占比、明细表以及缓存命中率。 Tracks input, output, cache read/write and reasoning tokens per model. Both the admin Overview and client settings chart hourly (today) and daily (7-day / 30-day) usage along with model share, breakdowns and cache hit rate.
Docker 自托管与隐私Docker self-hosting & privacy
一个脚本完成配置、拉取 GHCR 镜像（或源码构建 / 离线导入）与启动。Host 支持 amd64 与 arm64，box 为 amd64（ARM 主机需开启 binfmt/QEMU 或 Rosetta）。管理页（18080）和网页版（18081）默认仅监听 127.0.0.1；API Key 只写不读地存于 /data/model.env，全端遥测与错误上报均已关闭。 One script configures, pulls GHCR images (or builds from source / loads offline) and starts the stack. Host supports amd64 and arm64; box is amd64 (use binfmt/QEMU or Rosetta on ARM). Admin (18080) and Web (18081) bind 127.0.0.1 by default. API keys are write-only in /data/model.env, and telemetry is disabled across Host and clients.
局域网与加密隧道LAN & encrypted tunnel
无需云端账号，通过 5 分钟有效的 6 位一次性配对码或管理员密码接入。局域网可直接用 IP 连接，Android 客户端支持局域网 Host 扫描；外网访问可用内置的 Tailcat 加密组网（无需 Tailscale 账号），也支持 Tailscale、VPN 或 HTTPS 反向代理。 No cloud account needed: pair devices with a single-use 6-digit code (valid 5 minutes) or the admin password. Connect directly by LAN IP (with LAN host scanning on Android). For remote access, enable the built-in Tailcat encrypted tunnel (no Tailscale account required), or use Tailscale, VPN, or an HTTPS reverse proxy.
自托管客户端更新Self-hosted client updates
Host 管理员可在管理页「客户端更新」向自己 Host 上的已配对设备发布自行构建的各端安装包：Android 与桌面端支持增量补丁，桌面端更新清单采用 ECDSA P-256 签名校验，iOS 支持 itms-services（需 HTTPS）及 AltStore / SideStore 源。 Host administrators can publish self-built installers to paired devices from the admin console’s Client updates page: Android and desktop support delta patches, desktop update manifests are verified with ECDSA P-256 signatures, and iOS supports itms-services (HTTPS) and AltStore / SideStore sources.

快速开始Quick Start

准备一台装好 Docker（含 Compose v2）的 Linux 或 macOS 服务器，三步启动 Host 与共享执行容器。也可以把 AI 部署手册 发给编程助手自动完成。 Start on any Linux or macOS server with Docker and Compose v2 in three steps — or hand the AI agent deployment runbook to your coding assistant.

  1. 01 部署 Host 与执行容器Deploy Host & box

    克隆仓库后运行安装脚本。--local 会直接使用仓库内的 Compose 与环境变量模板；若拉取 GHCR 预构建镜像，需先用具备 read:packages 权限的令牌登录 ghcr.io。 Clone the repository and run the install script. Passing --local uses the templates from the repo directly. If pulling prebuilt GHCR images, sign in to ghcr.io with a token that has read:packages. 

    gh repo clone hongfaqiu/rokbot rokbot-src
# git clone https://github.com/hongfaqiu/rokbot.git rokbot-src

mkdir rokbot && cd rokbot
bash ../rokbot-src/host/release/install-images.sh --local

    脚本自动生成 .env（权限 0600）与随机密钥、拉取镜像、启动 host 与 box 容器并等待健康检查。离线部署可用 --offline，从源码构建详见 docs/AI-INSTALL.md。 The script creates .env (mode 0600) with random secrets, pulls images, starts host and box, and waits for health checks. Use --offline after docker load, or build from source via docs/AI-INSTALL.en.md.

  2. 02 初始化并连接客户端Initialize & connect

    读取一次性初始化密钥，打开管理页 http://127.0.0.1:18080/admin 设置管理员密码（12–128 位）。随后在「设备与通知」生成 6 位配对码即可配对原生客户端，或上传网页版界面包后访问 http://127.0.0.1:18081/web/。 Read the one-time setup key, open http://127.0.0.1:18080/admin, and set an admin password (12–128 characters). Create a 6-digit pairing code under Devices & notifications for native clients, or upload the web bundle to use http://127.0.0.1:18081/web/. 

    docker compose --env-file .env -f docker-compose.images.yml exec -T host cat /data/setup-key

    局域网访问请按需调整 ROKBOT_LISTEN_ADDRESS；无公网 IP 时可在管理页「远程访问」启用内置 Tailcat 加密组网。 Adjust ROKBOT_LISTEN_ADDRESS for LAN access, or turn on built-in Tailcat under Remote access when you don’t have a public IP.

  3. 03 配置模型与路由Configure models

    打开管理页「对话模型」（/admin?view=model）或用管理员密码配对的客户端设置：添加 OpenAI Chat、OpenAI Responses 或 Anthropic 模型服务并填入 Base URL 与 API Key，拉取模型列表、创建档案、测试连接并设置默认路由与备用链，保存后即可创建 Bot 开始对话。 Open Chat model in the admin console (/admin?view=model) or settings on an admin-paired client: add an OpenAI Chat, OpenAI Responses or Anthropic provider with your base URL and API key, fetch models, create profiles, test connections and set your default route and fallbacks. Save and start chatting.

获取客户端Getting the clients

本官网和 GitHub 仓库不提供、不分发任何客户端安装包（APK / IPA / DMG / EXE）。各端客户端只有两种获取方式：用仓库里的补丁工具自行构建，或者从你自己部署的 Host 获取。 Neither this website nor the GitHub repository hosts or distributes any client installers (APK / IPA / DMG / EXE). There are only two ways to obtain clients: build them yourself with the patch tools, or get them from your own deployed Host.

01用补丁工具自行构建Build yourself with patch tools

自备官方客户端安装包，在仓库根目录运行对应平台的补丁工具。工具会先按锁定配置校验文件大小和 SHA-256，只执行复制与新增字节，不反编译、不重写原版程序。桌面端和网页版省略 --source 时会按锁定配置拉取并校验官方包；Android 与 iOS 必须自备安装包。 Bring your own official installer and run the platform patch tool from the repository root. Tools verify size and SHA-256 against the pinned manifest and only copy/append bytes without decompiling or rewriting the binary. Desktop and web can fetch and verify pinned packages when --source is omitted; Android and iOS always require a package you supply. 

node android/release/patch-android.mjs \
  --input-apk /path/to/official-1.26.0.xapk \
  --output-apk android/output/rokbot-android-patched.apk

环境：Node.js 20+ · 输入：官方 1.26.0 (build 3212) 的 .xapk/.apks/.apk · 输出 16KB 对齐、v2/v3 签名 APK。详见 android/README.md。 Requires Node.js 20+ · Input: official 1.26.0 (build 3212) .xapk/.apks/.apk · Outputs a 16 KB-aligned v2/v3-signed APK. See android/README.en.md. 

python3 ios/release/patch-ios.py \
  --input /path/to/decrypted.ipa \
  --output ios/output/RokBot-Patched \
  --bundle-id dev.rokbot.local

环境：Python 3.9+ · 输入：自备解密官方 IPA（1.27.0 / 1.26.0 / 1.16.0）· 输出未签名 IPA 后用你自己的证书签名安装。详见 ios/README.md。 Requires Python 3.9+ · Input: your own decrypted official IPA (1.27.0 / 1.26.0 / 1.16.0) · Sign the output IPA with your own certificate. See ios/README.en.md. 

node mac/patchers/desktop/patch.mjs --source "/path/to/Grok_Bot_1.2.3.dmg"

环境：macOS + Node.js 22.12+ · 输入：官方 1.2.3 Apple Silicon .dmg 或 .app · 输出 mac/output.noindex/RokBot.app（控制本机 GUI 时加 --identity auto）。详见 mac/README.md。 Requires macOS + Node.js 22.12+ · Input: official 1.2.3 Apple Silicon .dmg or .app · Outputs mac/output.noindex/RokBot.app (add --identity auto for Mac GUI control). See mac/README.en.md. 

node windows/patchers/desktop/patch.mjs --source C:\path\to\Grok_Bot_1.2.3_Setup.exe

环境：Windows 10/11 x64 + Node.js 22.12+ · 输入：官方 1.2.3（或 0.71.2）x64 安装包 · 输出到 windows/output/（含便携版与用户安装版）。详见 windows/README.md。 Requires Windows 10/11 x64 + Node.js 22.12+ · Input: official 1.2.3 (or 0.71.2) x64 installer · Outputs portable and per-user builds in windows/output/. See windows/README.en.md. 

node web/patchers/patch.mjs --source /path/to/Grok_Bot_1.2.3_Setup.exe

环境：Windows/macOS/Linux + Node.js 22.12+ · 输出 web/output/RokBotLocal-web-1.2.3.zip，在管理页「网页版」上传，或加 --upload <Host 地址> 直接安装。详见 web/README.md。 Requires Node.js 22.12+ on any OS · Outputs web/output/RokBotLocal-web-1.2.3.zip to upload on the Host’s Web client page (or pass --upload <Host URL>). See web/README.en.md.

02从自己部署的 Host 获取Get from your own Host

Host 管理员可以把自行构建并签名的各端客户端发布到自己的 Host，供该 Host 下的设备安装与升级： A Host administrator can publish the installers they built and signed to devices connected to that Host:

  1. 管理员按方式一在本机构建并签名所需平台的安装包。 Build and sign the installers locally using Option 1.
  2. 在自己 Host 的管理页「客户端更新」选择平台（Android、iOS、macOS 或 Windows），上传并发布，可选基于旧版生成增量补丁。 On the Host admin console’s Client updates page, upload and publish for Android, iOS, macOS, or Windows (optionally generating delta patches).
  3. 已配对设备直接从该 Host 检查更新：Android 核对大小、SHA-256、包名与签名证书；macOS 与 Windows 核验 ECDSA P-256 清单签名并支持增量补丁；iOS 通过 itms-services（需 HTTPS）、AltStore / SideStore 源或签名工具安装。 Paired devices update directly from that Host: Android verifies size, SHA-256, package name and signing cert; macOS & Windows verify ECDSA P-256 manifests with delta patches; iOS installs via itms-services (HTTPS), AltStore / SideStore sources, or a signing tool.

首次安装前客户端尚未与 Host 配对，分发途径和范围由各 Host 管理员自行决定并负责。详见 docs/AGENT_DEPLOY.md。 For first-time installation before pairing, how installers reach users is decided by and is the responsibility of each Host’s administrator. See docs/AGENT_DEPLOY.en.md.
